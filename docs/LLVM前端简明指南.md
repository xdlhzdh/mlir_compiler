# LLVM 前端简明指南

## 一、先不谈术语：解析器到底在干嘛？

### 解析器的任务

把一串 **token**（词法分析结果）变成一棵**"结构正确的语法树"**

### 例如

```
a = 3 + 4;
```

不是简单的字符串，而是：

```
赋值语句
 ├─ 变量 a
 └─ 表达式 +
     ├─ 3
     └─ 4
```

> **解析器就像"语法法官"**：判断你写的程序是否符合语法规则。

---

## 二、什么是文法（Grammar）

我们用规则描述合法程序：

```
语句 → 赋值语句
赋值语句 → 标识符 = 表达式 ;
表达式 → 数字 | 标识符 | 表达式 + 表达式
```

这叫 **上下文无关文法 (CFG)**。

### 终结符 vs 非终结符

- **终结符**：出现在**最终句子**里的符号，**不能再被替换**。在编译器里通常就是词法分析得到的 **token**——如关键字、标识符、数字、`+`、`=`、`;` 等。推导结束时，句子里只剩终结符。
- **非终结符**：可以**被产生式继续替换**的符号，代表一类语法结构（如「语句」「表达式」）。产生式左边的都是非终结符；推导过程中会不断把非终结符替换成别的串，直到最后全是终结符。
- **直观**：终结符 = 真正写在程序里的「字」；非终结符 = 文法里的「占位名字」，用来组织规则。

**举例**：对上面的文法，符号可以这样区分：

| 符号 | 终结符 / 非终结符 | 说明 |
|------|-------------------|------|
| 语句、赋值语句、表达式 | **非终结符** | 会被产生式继续展开，不会出现在最终程序文本里 |
| 标识符、数字、`=`、`+`、`;` | **终结符** | 对应词法 token，最终程序就是由它们组成的 |

用规则把 `a = 3 + 4 ;` 推导出来的过程（每次只替换一个非终结符）：

```
语句
  → 赋值语句
  → 标识符 = 表达式 ;
  → a = 表达式 ;           （标识符 被替换成终结符 a）
  → a = 表达式 + 表达式 ;  （表达式 选「表达式 + 表达式」）
  → a = 数字 + 表达式 ;
  → a = 3 + 表达式 ;
  → a = 3 + 数字 ;
  → a = 3 + 4 ;
```

最后一行 **只剩终结符** `a`、`=`、`3`、`+`、`4`、`;`，不能再替换，推导结束。程序源码就是这串终结符。

## 三、FIRST 集合：一句话理解

**FIRST(X) = 从 X 开始，可能看到的第一个 token 是什么？**

### 例如

```
表达式 → number | identifier | '(' expression ')'
```

那么：

**FIRST(表达式) = { number, identifier, '(' }**

> **意思**：如果我正在解析一个"表达式"，那么下一个 token 只可能是这三种之一。

---

## 四、FOLLOW 集合：一句话理解

**FOLLOW(X) = 在某个句子中，X 后面可能紧跟的 token 是什么？**

### 例如

```
赋值语句 → identifier = expression ;
```

expression 后面一定是：`;`

所以：

**FOLLOW(expression) = { ';' }**

## 五、为什么要 FIRST / FOLLOW？如何检查冲突？

### 5.1 目的：判断「一个 token 够不够用」

**递归下降**（或 LL(1) 表驱动）解析器只能**向前看一个 token**（Lookahead）就选产生式。  
FIRST / FOLLOW 的作用是：**事先检查文法有没有「看一个 token 仍无法决定选哪条规则」的情况**——即 **FIRST/FOLLOW 冲突**。有冲突就不能用纯 LL(1)，需要改文法或加大前瞻（如 LL(2)）。

### 5.2 什么叫「冲突」？

当解析到非终结符 **A**，且存在两条产生式 **A → α** 和 **A → β** 时：  
若「下一个 token」同时落在「选 α 时可能出现的首 token」和「选 β 时可能出现的首 token」里，解析器就**无法单凭这一个 token 在 α 和 β 之间二选一**，这就是冲突。

### 5.3 如何检查冲突？

对每个非终结符 **A** 及其产生式 **A → α₁ | α₂ | … | αₙ**，做两类检查：

**① FIRST 与 FIRST 不能相交**

- 对任意两条不同产生式 **αᵢ** 与 **αⱼ**（i ≠ j），要求：**FIRST(αᵢ) ∩ FIRST(αⱼ) = ∅**。
- **原因**：若某个 token t ∈ FIRST(αᵢ) 且 t ∈ FIRST(αⱼ)，看到 t 时既可能该选 αᵢ 也可能选 αⱼ，无法只靠一个 token 区分。
- **检查方式**：对每对 (αᵢ, αⱼ) 算 FIRST(αᵢ)、FIRST(αⱼ)，看是否有公共元素。

**② 若有产生式可推出 ε，还要看 FOLLOW**

- **ε 是什么？** **ε（读作 epsilon）是约定符号，表示空串**——长度为 0、不包含任何 token 的串。文法里写「可选项」时经常用到它。
- **先解释两个说法**：
  - **「α 可推出 ε」**：用文法的产生式把 α 里的符号一步步替换下去，最终能变成**空串 ε**（不消耗任何 token），就称 **α 可推出 ε**（记作 `α ⇒* ε`）。
    - **例 1（可选项）**：要表达「可选分号」，不能写 `opt_semicolon → ';'`（这表示必须有分号）。应写成 `opt_semicolon → ε | ';'`，因此 **`opt_semicolon ⇒* ε`**。
    - **例 2（多步推导）**：若 `A → B`，`B → ε`，则 `A ⇒ B ⇒ ε`，所以 **`A ⇒* ε`**。
  - **「选 αᵢ 并推导出空」**：解析到 A 时，我们选了一条产生式 A→αᵢ；若 αᵢ 可推出 ε，则这条选择可以**不读任何 token** 就结束，相当于「A 在这里匹配了零个字符」。
- 因此：若某条 **αᵢ** 可推出 ε，则「选 αᵢ 并推导出空」也是一种合法可能；此时解析器不会从 αᵢ 里看到任何首 token，**下一个 token** 其实是「A 后面跟着的东西」，即 **FOLLOW(A)**。
- **要求**：对任意可推出 ε 的 αᵢ，与任意**其它** αⱼ，满足 **FIRST(αⱼ) ∩ FOLLOW(A) = ∅**。
- **原因**：若某 token t 既在 FOLLOW(A) 又在 FIRST(αⱼ)，看到 t 时既可能是「选了 αᵢ 推出空，t 是 A 后面的」，也可能是「该选 αⱼ，t 是 αⱼ 的开头」，无法区分。
- **检查方式**：先标出哪些 α 可推出 ε，再对每个这样的 A 算 FOLLOW(A)，检查是否与其它产生式的 FIRST 有交。

**FOLLOW 计算举例**：设文法为  
`S → A ';'`，`A → B`，`B → ε | 'x'`。
按「FOLLOW 的规则」来算：

> 这段里我们不引入额外记号：**FOLLOW(A) 的算法就是在所有产生式右边去找 A**，看 **A 后面可能紧跟什么终结符**；若 **A 后面那段可以为空**（或 A 已在末尾），就把“左边那个非终结符”的 FOLLOW 也并进来。

1. **FOLLOW(S)**：S 是起始符号 → 先放 `$`，即 FOLLOW(S) = { `$` }。  
   **`$` 就是“输入结束(EOF)”这个标记**：表示整个输入已经读完了（不需要在源码里真的写 `$`）。
2. **FOLLOW(A)**：在产生式 `S → A ';'` 里，**A 后面紧跟着 `';'`**。  
   - 规则 1：把 **A 后面的那段**当成 `';'`，则 FIRST(`';'`) = { `';'` } → **FOLLOW(A) ⊇ { `';'` }**。  
   - 得 **FOLLOW(A) = { `';'` }**。
3. **FOLLOW(B)**：在产生式 `A → B` 里，**B 在最末尾**（等价于「B 后面没有 β / β 为空」）。  
   - 规则 2：因此 **FOLLOW(A) ⊆ FOLLOW(B)**。  
   - 所以 **FOLLOW(B) ⊇ FOLLOW(A) = { `';'` }**，即 **FOLLOW(B) = { `';'` }**。

于是：B 有分支可推出 ε（`B → ε`），另一分支为 `B → 'x'`。要满足 FIRST(`'x'`) ∩ FOLLOW(B) = { `'x'` } ∩ { `';'` } = ∅，成立，无冲突。  
**人话**：看到 `;` 时选 B→ε（B 不消耗任何 token，`;` 留给后面）；看到 `x` 时选 B→`'x'`，不会混淆。

### 5.4 小结

| 检查项 | 条件 | 不满足时的含义 |
|--------|------|----------------|
| FIRST 互不相交 | FIRST(αᵢ) ∩ FIRST(αⱼ) = ∅ | 同一 token 可能是 αᵢ 或 αⱼ 的开头，无法选择 |
| ε 与 FOLLOW | 若 `αᵢ ⇒* ε`，则 FIRST(αⱼ) ∩ FOLLOW(A) = ∅ | A 推出空后紧跟的 token 与选 αⱼ 时的首 token 重叠，无法选择 |

全文满足上述两类检查 → 文法是 **LL(1)**，可以只靠一个 token 的 Lookahead 无冲突地解析。

## 六、什么是 Lookahead（前瞻）

解析器看：

- **当前非终结符** + **下一个 token**

来决定：

- **用哪条产生式**

### 例如

```
语句 → 赋值语句 | 表达式语句
```

两者都以 identifier 开头：

```javascript
a = 3;    // 赋值语句
a + 3;    // 表达式语句
```

看到 `a`：

- ❌ **无法判断是哪一种**
- → 这时 **FIRST 集合冲突**

## 七、LL(1) 是什么？

### 拆开理解

| 字母 | 含义 |
|------|------|
| **L** | 从左到右读 |
| **L** | 最左推导 |
| **1** | 看 1 个 token |

**LL(1) = 只看一个 token 就能决定语法规则的解析方法**

### 什么是「最左推导」（Leftmost Derivation）

**最左推导**指：在推导过程的每一步，如果当前串里有多个非终结符，**永远优先展开最左边那个非终结符**。

> 你在「从左到右」读 token 时，也会更希望先把“最左边那块语法结构”确定下来；LL 解析的推导顺序与这个直觉是一致的。

#### 举个最小例子

文法：

```
S → A B
A → a
B → b
```

要推导出字符串 `ab`，最左推导过程是：

```
S  ⇒ A B
   ⇒ a B    （先展开最左非终结符 A）
   ⇒ a b
```

#### 为什么 LL 解析强调最左推导？

- **同步性**：LL 解析器从左往右读输入，通常希望尽快确定“当前读到的 token 属于哪一段最左侧结构”。
- **预测性**：LL 是自顶向下（Top-down）构造语法结构，先从起始符号开始，一层层往下展开；“每步展开最左非终结符”能让这个过程更稳定、更容易用一个 Lookahead 做选择。

### 对比：最右推导（Rightmost Derivation）

**最右推导**则是每一步优先展开最右边的非终结符。对上面的文法，最右推导是：

```
S  ⇒ A B
   ⇒ A b
   ⇒ a b
```

它常出现在 **LR** 体系里（更准确地说：LR 通常构造的是“最右推导的逆过程”），因此你会看到 LL/LR 在推导顺序上一个偏“最左”、一个偏“最右/逆推”。

### 正式条件

对任意非终结符 A：

```
A → α | β
```

必须满足：

1. **FIRST(α) ∩ FIRST(β) = ∅**

2. 如果 α 可推出 ε：
   - **FIRST(β) ∩ FOLLOW(A) = ∅**

## 八、冲突的直观例子

```
statement → assignment | exprStmt

assignment → identifier '=' ...
exprStmt → identifier '+' ...
```

FIRST 都是：**{ identifier }**

→ **冲突** → **不是 LL(1)**

---

## 九、解决方法：左因子消除

改写为：

```
statement → identifier statement'
statement' → '=' ... | '+' ...
```

现在：

**FIRST(statement') = { '=', '+' }**

不冲突了 ✅

## 十、FIRST / FOLLOW 的正式定义（但人话版）

### FIRST(X)

**规则：**

1. X 是终结符 → **FIRST(X) = { X }**
2. X → Y... → **FIRST(X) 包含 FIRST(Y)**
3. 如果 Y 可为空 → **看后面的**

### FOLLOW(X)

**规则：**

1. 若 S → α X β，则 **FIRST(β) ⊆ FOLLOW(X)**
2. 若 S → α X 或 β 可空，则 **FOLLOW(S) ⊆ FOLLOW(X)**
3. **起始符号包含 $**

## 十一、LL vs LR 的区别（重要）

| 特性 | LL(1) | LR |
|------|-------|-----|
| **构造方向** | 从上往下 | 从下往上 |
| **推导方式** | 最左推导 | 最右推导逆 |
| **能力** | 弱 | **强** |
| **实现** | 简单 | 复杂 |
| **工业使用** | 少 | **多** |

---

## 十二、LR 解析器是什么？

### LR 解析原理

**根据"已经读入的 token" + 状态栈**  
决定：**移进（shift）**还是**归约（reduce）**

### 优点

- ✅ 能处理**左递归**
- ✅ 能处理**复杂文法**
- ✅ **无需人工消除冲突**

### 缺点

- ❌ 难写
- ❌ 状态机复杂
