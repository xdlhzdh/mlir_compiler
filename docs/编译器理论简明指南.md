# 解析器理论简明指南

## 一、先不谈术语：解析器到底在干嘛？

### 解析器的任务

把一串 **token**（词法分析结果）变成一棵**"结构正确的语法树"**

### 例如

```
a = 3 + 4;
```

不是简单的字符串，而是：

```
赋值语句
 ├─ 变量 a
 └─ 表达式 +
     ├─ 3
     └─ 4
```

> **解析器就像"语法法官"**：判断你写的程序是否符合语法规则。

---

## 二、什么是文法（Grammar）

我们用规则描述合法程序：

```
语句 → 赋值语句
赋值语句 → 标识符 = 表达式 ;
表达式 → 数字 | 标识符 | 表达式 + 表达式
```

这叫 **上下文无关文法 (CFG)**。

---

## 三、FIRST 集合：一句话理解

**FIRST(X) = 从 X 开始，可能看到的第一个 token 是什么？**

### 例如

```
表达式 → number | identifier | '(' expression ')'
```

那么：

**FIRST(表达式) = { number, identifier, '(' }**

> **意思**：如果我正在解析一个"表达式"，那么下一个 token 只可能是这三种之一。

---

## 四、FOLLOW 集合：一句话理解

**FOLLOW(X) = 在某个句子中，X 后面可能紧跟的 token 是什么？**

### 例如

```
赋值语句 → identifier = expression ;
```

expression 后面一定是：`;`

所以：

**FOLLOW(expression) = { ';' }**

---

## 五、为什么要 FIRST / FOLLOW？

因为：

> **递归下降解析器**（或表驱动解析器）必须只靠**"下一个 token"**就决定走哪条语法规则

这就叫：**Lookahead（前瞻）**

---

## 六、什么是 Lookahead（前瞻）

解析器看：

- **当前非终结符** + **下一个 token**

来决定：

- **用哪条产生式**

### 例如

```
语句 → 赋值语句 | 表达式语句
```

两者都以 identifier 开头：

```javascript
a = 3;    // 赋值语句
a + 3;    // 表达式语句
```

看到 `a`：

- ❌ **无法判断是哪一种**
- → 这时 **FIRST 集合冲突**

---

## 七、LL(1) 是什么？

### 拆开理解

| 字母 | 含义 |
|------|------|
| **L** | 从左到右读 |
| **L** | 最左推导 |
| **1** | 看 1 个 token |

**LL(1) = 只看一个 token 就能决定语法规则的解析方法**

### 正式条件

对任意非终结符 A：

```
A → α | β
```

必须满足：

1. **FIRST(α) ∩ FIRST(β) = ∅**

2. 如果 α 可推出 ε：
   - **FIRST(β) ∩ FOLLOW(A) = ∅**

---

## 八、冲突的直观例子

```
statement → assignment | exprStmt

assignment → identifier '=' ...
exprStmt → identifier '+' ...
```

FIRST 都是：**{ identifier }**

→ **冲突** → **不是 LL(1)**

---

## 九、解决方法：左因子消除

改写为：

```
statement → identifier statement'
statement' → '=' ... | '+' ...
```

现在：

**FIRST(statement') = { '=', '+' }**

不冲突了 ✅

---

## 十、FIRST / FOLLOW 的正式定义（但人话版）

### FIRST(X)

**规则：**

1. X 是终结符 → **FIRST(X) = { X }**
2. X → Y... → **FIRST(X) 包含 FIRST(Y)**
3. 如果 Y 可为空 → **看后面的**

### FOLLOW(X)

**规则：**

1. 若 S → α X β，则 **FIRST(β) ⊆ FOLLOW(X)**
2. 若 S → α X 或 β 可空，则 **FOLLOW(S) ⊆ FOLLOW(X)**
3. **起始符号包含 $**

---

## 十一、LL vs LR 的区别（重要）

| 特性 | LL(1) | LR |
|------|-------|-----|
| **构造方向** | 从上往下 | 从下往上 |
| **推导方式** | 最左推导 | 最右推导逆 |
| **能力** | 弱 | **强** |
| **实现** | 简单 | 复杂 |
| **工业使用** | 少 | **多** |

---

## 十二、LR 解析器是什么？

### LR 解析原理

**根据"已经读入的 token" + 状态栈**  
决定：**移进（shift）**还是**归约（reduce）**

### 优点

- ✅ 能处理**左递归**
- ✅ 能处理**复杂文法**
- ✅ **无需人工消除冲突**

### 缺点

- ❌ 难写
- ❌ 状态机复杂

---

## 十三、现实世界

| 工具 | 类型 |
|------|------|
| 手写递归下降 | LL |
| **clang / gcc** | **LR** |
| **yacc / bison** | **LALR** |
| **ANTLR** | **LL(*)** |

---

## 十四、一个直觉总结

| 概念 | 类比 |
|------|------|
| **FIRST** | "这个东西开头长啥样" |
| **FOLLOW** | "它后面通常跟啥" |
| **Lookahead** | "偷看下一个词" |
| **LL(1)** | "只偷看一个就够" |
| **LR** | "先读完整再判断" |
